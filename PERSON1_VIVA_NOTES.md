# Person 1 Viva Examination Notes (Automata Theory)

These concise notes are prepared for the oral examination (viva) of the Smart Metro Ticketing and Journey Validation System. Each topic contains a 3 to 6 sentence plain-English explanation written for clarity, theoretical rigor, and direct defense.

---

### 1. Why a missing transition goes to the dead state

In formal Automata Theory, the transition function $\delta$ of a Deterministic Finite Automaton (DFA) is a total function, meaning it must be defined for every pair of state and alphabet symbol $(q, a) \in Q \times \Sigma$. In real-world software, incomplete specifications or invalid user actions often omit transitions. Rather than crashing or leaving behavior undefined, an automaton handles missing transitions by routing them to a designated "dead state" (also called a trap or sink state) that permanently loops to itself on all input symbols. Because the dead state is non-accepting and cannot reach any accepting state, any string that triggers an undefined move is safely and permanently rejected. This cleanly separates operational errors from normal program execution while maintaining theoretical completeness.

### 2. How subset construction works (including $\epsilon$-closure)

Subset construction (the powerset construction algorithm) converts a Nondeterministic Finite Automaton (NFA) with optional $\epsilon$-transitions into an equivalent DFA. Because an NFA can be in multiple states simultaneously, each state in the resulting DFA represents a specific *subset* of NFA states. The algorithm begins at the DFA start state, which is the $\epsilon$-closure of the NFA start state—the set of all states reachable by taking zero or more spontaneous $\epsilon$-transitions without consuming any input. For each discovered subset and each alphabet symbol $a$, the DFA transitions to the $\epsilon$-closure of all states reachable on $a$ from any state in that subset. A DFA state is marked accepting if its subset contains at least one accepting state of the original NFA, guaranteeing that the DFA recognizes the exact same language.

### 3. Why two states are equivalent (Myhill-Nerode theorem and table-filling)

According to the Myhill-Nerode theorem, two states $p$ and $q$ in a DFA are equivalent (indistinguishable) if and only if for every possible input string $w \in \Sigma^*$, reading $w$ from state $p$ and reading $w$ from state $q$ either both lead to accepting states or both lead to non-accepting states. If there exists even one string $w$ that distinguishes them—causing one state to accept and the other to reject—the states are distinguishable and cannot be merged. The table-filling algorithm discovers distinguishable states systematically from the bottom up: it first marks all pairs containing one accepting and one non-accepting state (distinguished by the empty string $\epsilon$), and then iteratively marks pairs $(p, q)$ whose transitions on some symbol lead to an already marked pair. Any pairs left unmarked when no more marks can be added are genuinely equivalent, meaning they exhibit identical future behavior and can safely be merged into a single state.

### 4. The difference between Moore and Mealy outputs

The fundamental difference between Moore and Mealy machines lies in how their output functions are defined. In a Moore machine, the output depends exclusively on the current state ($\lambda: Q \to \Gamma$), meaning the output is produced upon entering or remaining in that state regardless of which input triggered the move. In a Mealy machine, the output depends jointly on both the current state and the incoming input symbol ($\lambda: Q \times \Sigma \to \Gamma$), meaning the output is generated by the transition itself. Consequently, a Mealy machine can respond immediately to an input with different messages from the same starting state, often requiring fewer states to describe the same reactive behavior. For comparative analysis in our gate simulation, both machines are clocked to return one output per input symbol processed, showing how state notifications (Moore) align with transition events (Mealy).

### 5. Why Over-Travel (O) and Over-Time (T) both lead to the same Excess Pending state (JE)

In our metro system, over-travel (riding beyond the paid destination) and over-time (staying inside longer than the 19-minute loop limit) represent two different physical events, but they require the exact same operational and financial resolution. When either event occurs, the exit gate must remain locked, the passenger remains accounted for inside the system, and a monetary penalty must be cleared before exit is granted. Routing both symbols $O$ and $T$ from $J1$ to the common state $JE$ captures this identical control-flow logic without needlessly duplicating states. Once in $JE$, the passenger must pay the required charge (symbol $P$), which transitions the ticket to the normally exited accepting state $J2$ and unlocks the gate.
